## ssh -G output (after `sbx setup ssh`)

```
user _default_user_
hostname orca-spike.sbx
port 22
identitiesonly yes
identityfile /dev/null
proxycommand "/opt/homebrew/bin/sbx" ssh proxy %n
```

- Plain `ssh orca-spike.sbx -- echo ok` → `ok`. Setup output documents `sftp <name>.sbx` explicitly (relay's SFTP upload path exists).
- **`%n` is NOT expanded by `ssh -G`** — `emit_connection_json` must substitute `%n`/`%h` with `<name>.sbx` before emitting `proxyCommand` (Orca will not expand OpenSSH tokens).
- `identityfile /dev/null` — auth rides the proxy tunnel, no key involved. Emission should OMIT `identityFile` when it resolves to `/dev/null` (Orca must not try to load it as a key).
- `user _default_user_` — placeholder accepted by the proxy. Which username Orca's target needs (`_default_user_` vs `agent`) is decided empirically in Task 2.

## Task 2: Orca relay

**Import picker**: `Host *.sbx` is invisible — Orca's parser drops wildcard patterns (`src/main/ssh/ssh-config-parser.ts:52`). Workaround: concrete `Host orca-spike.sbx` entry prepended to `~/.ssh/config` (backup at `~/.ssh/config.orca-spike-backup`). With it, the picker showed the host and import succeeded.

**Token expansion**: Orca expands only `%h`/`%p` in ProxyCommands (`src/main/ssh/ssh-proxy-command.ts:111-112`), never `%n`. The sbx managed block uses `%n`. Our concrete entry overrides with `%h` (identical value since hostname == alias). → **The recipe must emit a fully pre-expanded proxyCommand — no `%` tokens.**

**First connect failed — exit 255, root-caused and minimally reproduced**: Orca's system-ssh relay upload forces ControlMaster multiplexing (`system-ssh-args.ts`), overriding sbx's `ControlMaster no` config. CLI repro: identical tar-over-ssh pipeline with `-o ControlMaster=auto -o ControlPath=… -o ControlPersist=300` exits **255**; with `-S none` exits **0** (extract verified). The sbx proxy cannot serve as a mux master.

- Spike fix: per-target Advanced toggle "Reuse SSH connection for faster setup" → OFF (`systemSshConnectionReuse: false` → `-S none`).
- **Recipe gap found**: `EphemeralVmRecipeSshTargetSchema` has NO `systemSshConnectionReuse` field — a recipe cannot express the opt-out today. Needs a tiny upstream schema+plumbing addition (or Orca honoring resolved `ControlMaster no`). This is the first concrete core change to propose upstream.

**After the mux opt-out — remaining blockers found and fixed, then full PASS:**

1. **node-pty source build**: the relay's first connect builds node-pty; the claude template has no C++ toolchain (`make: g++: No such file or directory`, exit 127). Fix: `sudo apt-get install -y build-essential` inside the sandbox (agent has sudo; apt worked under the network policy). → create.sh requirement.
2. **git author identity**: Orca's project-create preflight requires `git config --global user.name/email` on the SSH host. Fix: mirror the host's global identity into the sandbox. → create.sh requirement.

**PASS evidence** (verified via `sbx exec`):
- Linked worktree created by Orca's remote git flow: `/home/agent/project/test-project` (master) + `test-project-new-feature` (new-feature) — `.git` pointer resolves inside the VM.
- Claude session dirs exist in `~/.claude/projects/` for both workspaces; `claude --dangerously-skip-permissions` running under the relay; Matt reports status UX working normally.
- Two `relay.js` processes + relay-watcher healthy.
- Latency: `sbx exec` revive of stopped sandbox ~1.8s; create ~2m; steady-state terminal indistinguishable from a normal SSH host (SSH traffic bypasses the sbx CLI).

## Task 3: decision

**GATE: PASS.** Relay criteria 1–4 all pass. Reconciliation applied to plan Tasks 4–6:
- stub `sbx ls --json` default → `{"sandboxes":[]}` (object, not array)
- resume: no `sbx start` in v0.38 → `sbx exec NAME -- true` (auto-starts, ~2s)

**Carried risk** (Task 11 tests empirically): recipe-created runtime-owned SSH targets cannot set `systemSshConnectionReuse: false` — if their connect path uses system ssh with mux, it fails exit-255 like the spike did before the toggle. Fallback: propose upstream addition of `systemSshConnectionReuse` to `EphemeralVmRecipeSshTargetSchema` + plumbing (one-line spread in `upsertRuntimeOwnedTarget`).

**Deviation**: spike sandbox `orca-spike` + ssh-config entry + Orca host kept until Task 11 completes (working reference environment); cleanup moves to end of Task 11.
